# 本机连续性筛查

此功能需要另行配置本机 IK 控制器、机械臂模型及筛查数据；普通 `--setup` 只配置轨迹和视频访问，不会安装 IK 求解环境。缺少结果时显示未知/待筛查，不能视为通过。求解器、原始数据和本机配置不随此仓库发布。

在查看器选中记录和机械臂，将“筛查标准”切换为“相邻帧能否连续衔接”，点击“本机检查连续衔接”。尚未检查的记录显示未知，不沿用旧的通过标签。

检查每一帧以及从上一帧到这一帧的衔接。每秒汇总一段，跨段、跨 PA 边界仍然检查。失败后允许重新求解以诊断后续小段，但整条记录保持不通过。红色指本次有限搜索未通过，并非证明机械臂绝对无法完成任务。

## 批量运行

在项目目录下，使用原 IK 环境运行（本机当前参考数据在相邻的 `umi_ik` 目录）：

```bash
../umi_ik/cad_env/bin/python app/batch_continuity.py --root ../umi_ik --task all
```

`--task cup` 只查杯子；`--task phone` 只查手机；`--limit 3` 先查三条记录。该命令检查 Franka/OpenArm 左右单臂四项，最多尝试四个初始关节种子，同一次尝试保持整个轨迹的放置变换不变。任一尝试全程通过才标通过，不拼接不同尝试的结果。

默认同时运行 4 个独立求解进程，可用 `--workers 8` 调整。选择记录中的“连续通过 / 连续未通过 / 待筛查 / 检查异常”每 10 秒更新：选定机械臂时显示该臂结果，未选时显示上述四项加 G2 双臂的五项交集。任一项失败即可标记未通过，五项全通过才标通过。批量期间暂停单条复查按钮，避免同时写同一结果文件。

G2 参考配置另外运行：

```bash
../umi_ik/cad_env/bin/python app/batch_g2_continuity.py --root ../umi_ik --workers 6
```

G2 使用耦合的 14 关节双臂求解，以及双臂/机身/臂间碰撞检查；同一条记录两手共享一个固定刚体放置变换。通过要求一次尝试覆盖所有帧。批量判定对失败尝试在首个断点停止，再试其他初始关节种子；没有检查的后续帧保留 unknown，不标成通过或失败。查看器会注明这一点，批量结束后可点击“本机检查连续衔接”补全该参考放置下的局部分段诊断。G2 汇总为 `batch_g2.json`。

这是 AgiBot G2 参考模型，不是已验证的 TX-G2；其虚拟工具变换未经 YUBI 标定，碰撞模型不含实际夹爪、桌面和任务物体。

批量可按 Ctrl+C 中断，再运行相同命令；程序复用匹配版本和输入的已完成结果。结果保存在本机 `umi_ik/continuity_diagnostics`，不改原数据和旧筛查标签。`batch_all.json`（或 cup/phone）列出编号、episode、臂型、侧别和通过情况。程序错误标为 error，不算 IK 筛除。

## 检查范围

- 每帧 TCP 位置误差 ≤1 mm，姿态误差 ≤0.5°。
- 关节角范围、模型中的静态速度上限；逐帧求解范围限制在上一帧可到达的关节区间。
- 每帧自身/机身碰撞，以及相邻关节姿态之间按最大关节步长 0.02 rad 采样检查碰撞。
- 可用 `--acceleration 10` 加入 10 rad/s² 的参考加速度上限；这是实验参数，不是厂家认证参数。默认不检查加速度。
- 默认采样率 30 Hz，可用 `--fps` 指定。开始/结束速度没有设为零。

这仍是参考配置下的离线筛查：没有扭矩、动力学、桌面/物体碰撞、Franka 随关节位置变化的速度限制验证；插值采样也不是严格的连续碰撞检测。显示的原始轨迹用于定位问题，旧“参考 IK”播放关节轨迹不是新求解结果。单帧失败时保留断点，重启后局部通过不代表原轨迹从头可连续执行。
